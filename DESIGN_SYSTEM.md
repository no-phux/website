# phux site design system

**TL;DR.** phux.sh draws every colour, type size, radius, shadow, spring and
material from the phux-brand design tokens. This page holds only the
site-specific rules on top of them; it restates no values. The tokens, their
roles and their accessibility guarantees are documented in phux-brand
([`guidelines/USAGE.md`, "Design tokens"](https://github.com/no-phux/phux-brand/blob/main/guidelines/USAGE.md#design-tokens),
shipped in every release as `USAGE.md`) and in the phux live contract
([`docs/design-language.md`](https://github.com/no-phux/phux/blob/main/docs/design-language.md)).
See them rendered as this site renders them at `/_design`.

## Tokens

- **Source.** `src/styles/brand-tokens.css` is generated by phux-brand and
  installed by `python3 scripts/brand.py sync` (pinned in `brand.lock.json`;
  `bun run brand:check` refuses hand edits). It is the only file allowed to hold
  style values. `src/data/vocabulary.json` (status words and ICU plurals) is
  synced the same way; read it through `src/lib/vocabulary.ts`, never as English
  literals.
- **Names.** Read tokens as `var(--phux-<group>-<name>)`. Tailwind utilities
  reach them through the export's `@theme inline` block (`bg-phux-layer-raised`,
  `rounded-phux-md`, `font-phux-mono`). Pages that do not load `global.css`
  import `src/styles/standalone-tokens.css`.
- **Site aliases.** `global.css` maps the site's older `--color-*` names onto
  tokens so components keep working: `bg`/`bg-soft`/`surface` are layers,
  `fg`/`dim`/`muted`/`subtle` are text tiers, `rule` is `border.base`, `accent` is
  `accent.accent`, and `signal`/`attention`/`warn`/`error`/`cyan` are status
  tones. New code uses `--phux-*` directly.
- **Meaning.** Colour means state or identity. Accent marks focus and the one
  primary action; status tones mark agent state and always travel with their
  word and mark; search highlights use `match.*`, code uses `syntax.*`, diffs use
  `diff.*`. Text on an accent surface uses `accent.on_accent`; accent-coloured
  text uses `accent.accent_text`.
- **Type** is the seven roles (`micro`, `caption`, `label`, `body`, `lead`,
  `title`, `display`) in `rem`, so browser text size applies. Marketing
  headlines may be fluid between `display` and 3rem with `clamp()`. Emphasis
  comes from weight or ink, never opacity. Inter is self-hosted
  (`public/fonts/InterVariable.woff2`, preloaded on the landing) and answers the
  token stack's first family; Paper Mono is the mono family.
- **Shape and depth.** Radii follow the role table (controls `sm`, cards and
  panels `md`, dialogs `lg`, glass windows `xl`, pills `full`). Shadows are only
  the elevation tiers (`flat`, `raised`, `floating`, `overlay`).
- **Motion.** Transitions use the spring pairs as
  `var(--phux-motion-<spring>-duration) var(--phux-motion-<spring>-easing)`:
  `control` for hover and colour, `press` for the 0.98 press scale, `select` for
  moving indicators, `pop`/`drawer` for overlays. The terminal cursor's blink is
  the one site constant (`--cursor-blink-period`): it follows terminal
  convention, not a UI spring.
- **Materials.** The live shell is `material.glass` (`--phux-glass-tint`, blur
  `--phux-glass-blur-floating`, falling back to `--phux-glass-fallback` without
  backdrop blur). The hero download is the one `material.metal` control in view;
  every other primary action is a flat accent fill.
- **States.** One focus ring for every focusable element: an `outline` (never a
  shadow, so forced colours keep it) in `border.focus`. Hover adds `wash.hover`,
  press uses `wash.press` instead, invalid fields take a `status.failed` border.
- **Layout.** Use logical properties (`padding-inline-start`,
  `inset-inline-end`, `text-align: start`).

## Modes

| Surface | Selector | Mode |
|---|---|---|
| Marketing (`BaseLayout`, `/embed`, `/concepts`) | `data-design="terminal"`, `data-theme="dark"` | the house look, dark. Marketing stays dark until every component reads tokens (the ratchet below reaches zero), then follows the system. |
| Documentation | `data-design="reader"` with a `.dark`/`.light` class | the reader variant, following the Light/Dark/System selector |
| Live shell | `.terminal-surface` | glass in the page's mode; program output is not recoloured |

`brand-tokens.css` handles increased contrast (`prefers-contrast: more`, not
in the reader), forced colours (every role becomes a system colour), reduced
motion and reduced transparency globally; pages add nothing for them. Head
`theme-color` metas read the ground token at build time (`src/lib/brand-tokens.ts`).

## Documentation reader

The reader is the documented token variant `[data-design="reader"]`: paper and
ink with one warm accent, verified by phux-brand like the house look, and a
15/1.6 `lead` for long-form reading. Radius, space, motion and status are
shared with the house look. `src/styles/reader/tokens.css` only names the
reader's tokens for its stylesheets and maps Fumadocs' `--color-fd-*` palette
(including the portalled search dialog) onto them. Every reader rule lives in
`src/styles/reader/*.css` (imported in order by `src/styles/reader.css`),
scoped to `html[data-design="reader"]`; keep reader rules there rather than
appending a theme override to `global.css`.

- Body is `lead` in a 38rem column (`--reading-width`). The page title is
  `display`, H2 `title`, H3 `lead` at semibold. Utilities stay at `label` or
  larger; commands remain zoomable and horizontally scrollable.
- Panels (code, tables, overview cards) share one recipe: `layer.raised` fill,
  `border.base` hairline, `radius.md`, `elevation.raised`.
- The wordmark is lowercase `phux`; navigation uses sentence case.
- The native Theme selector (sidebar foot) offers System, Light and Dark;
  System is the default. next-themes owns persistence; a head script applies the
  saved preference before paint and across Astro document swaps.

## Landing and live shell

The homepage opens with a two-column hero: headline, description and download
on the left; an alert, lean silver fox on the right (`src/components/fox/Fox.astro`,
a site illustration, not a change to the identity kit). Its halo is
`--fox-halo`, a token wash. Keep the silhouette still: only the eyes and a
sub-two-degree head response follow the pointer, bounded and damped; reduced
motion, hidden tabs and offscreen art settle to a static pose. On phones the fox
sits below the download, above the real product comparison.

The headline is the joke: **Oh good, another terminal multiplexer for agents.**
One paragraph (`HOME.lede`) owns up to it and then says what phux does. There is
no eyebrow and no second slogan. `HOME` in `src/lib/site.ts` owns the headline,
lede and metadata; `SITE.tagline` keeps the technical category for
documentation. Keep the download and the start of the product screenshot within
the first screen.

`Exhibits.astro` shows what phux does as four rows: a short statement and two
or three plain sentences on the left, and on the right what phux prints,
captured from a real server and set in one panel recipe in Paper Mono. At most
one line per panel takes the `needs_you` tone: the line the row is about. No
window chrome, typing animation or invented activity. Do not add a competitor
pitch or feature matrix, and never use “keep your editor” as the proposition.

The primary install action follows the visitor's OS, not viewport width.
macOS keeps the Mac download; Linux opens the CLI installer; Windows leads to
installation instructions with the required WSL 2 coordinator noted. Desktop
0.50.0+ publishes a native Windows client; do not rewrite that as unavailable.
iPhone/iPad use the TestFlight handoff; Android gets the platform chooser.
Email remains an explicit, viewport-safe alternative. The closing action follows
the same selection. Static/no-JavaScript HTML uses a real installation-guide
link; detection is client-side only.

The landing carries a short top bar (mark, wordmark, Docs, a local GitHub
badge). The headline, install action and fox lead a draggable TUI/GUI
comparison of real captures, with a native range input for pointer, touch and
keyboard. Without JavaScript, show both previews and hide the inert controls.
The "All platforms" disclosure holds the CLI, Desktop and Mobile targets in one
`layer.sidebar` panel; Mobile swaps the command line for native access and
optional email. The quiet footer keeps Demos, More, Privacy and Support.

The glass live workspace stays inline below the fold, with a visible anchor from
the hero and a separate full-shell link. Its iframe does not exist until the
section intersects the viewport; leaving view or hiding the tab removes it after
a short grace period, and returning starts a fresh demo. Say so next to the
workspace. No terminal/GPU/WASM JavaScript or demo-origin preconnect belongs in
the initial viewport's resource budget.

The workspace is one glass window holding the real phux client. The client paints
text on a transparent canvas and publishes each pane's cell rectangle; the page
draws dividers and the focused tile from that geometry. Glyphs are never scaled:
the grid is fitted in whole cells, at one fixed height per breakpoint so
connecting does not move the page. An untouched demo runs its intro and makes one
split when there is room; the first pointer or key press ends all automation.

Below the workspace, the illustrated tour shows a server, clients and signals
travelling along connections. It autoplays only while on screen, with pause and
chapter controls; reduced motion shows settled chapters. The live-demo
invitation is always visible as a bottom chip. `/more` retains its opt-in,
pausable, scrubbable explainer.

The live shell's dialog offers **Pair your phone**: a line that expands into a
QR (a light tile, the only light surface in the dialog) with the status beneath.
The phone opens `/phone#CODE` and lands in the same shell. The link is
single-use and expires with the session; the code never appears in a URL the
site's logs would keep. While a phone is attached the shell follows the newest
screen's size, and the line says "Phone linked".

The hosted `/embed` shell and live dialog share the `.terminal-surface` glass, a
single rounded frame and an opaque readable terminal canvas. Pane controls sit
below the canvas as icons with accessible names and a labelled primary Split
pane action. The Info disclosure opens an inspector for runtime, limits,
shortcuts and session controls. OAuth returns wake the visibility-hydrated tour
dialog.

## Article structure

An article is a title, one useful full summary, and the author's content — in a
single 38rem column. No breadcrumb, no section eyebrow, no right-hand rail. Do not
repeat the source TL;DR in the body, hide the summary behind a disclosure, or
inject another section primer ahead of the author's content.

Page actions are a quiet icon row at the right of the title line: copy the page
as Markdown, view the `.md` twin, and view the exact source on GitHub (pinned to
the synchronized revision). Each icon has an accessible name and a tooltip; copy
outcomes are announced in a polite live region. The links work without
JavaScript.

The article ends with quiet previous/next links from the page tree, then a meta
line (non-stable status, wire version on protocol pages, Privacy, Support).
Heading IDs and deep links must survive presentation changes.

Prose links are ink with an accent underline; headings remain ordinary text with
discoverable anchor links. Headings have generous separation without a rule
above every section. Callouts are bold lead-ins or a plain quoted aside, not
coloured boxes; reserve them for warnings or meaningful constraints.

## Static technical content

Fenced code stays in the original Shiki-highlighted HTML, coloured by the brand
`syntax.*` roles (`src/lib/syntax-theme.ts`), so it follows the mode and increased
contrast and never borrows a status tone. No second React root,
shadow DOM, line-selection model, or client-side syntax renderer replaces it.
A lightweight enhancement adds a small copy icon inside the panel's top-right
corner (accessible name "Copy code") and a polite status; clipboard failure
shows how to copy manually. Code remains selectable, searchable with browser
Find, and keyboard-scrollable. Without JavaScript, the static code remains
readable and selectable.

Inline code is a small tinted pill. Keys are raw `<kbd>` in the Markdown
(`<kbd>C-a</kbd> <kbd>d</kbd>`) and render as small raised keycaps in prose,
lists, and tables alike.

Tables are light and compact: muted header text over one rule, faint row
separators, no zebra fill, on the shared panel. They retain native table
semantics inside a labelled, focusable scrolling region. Code and table overflow
stays local to its panel rather than widening the page. Never wrap byte
diagrams or clip commands to fit a viewport.

## Navigation and overview

`/overview` is the primary docs home. Its first-run steps, model figure, and
guide cards connect the reader's goal to a working path. `/docs` remains the
addressable complete index and leads the first group after the overview.

The sidebar is the only navigation: the fox mark and wordmark, a pill search
button with its shortcut, then one flat list. `scripts/docs-output.ts` derives
it from the catalog (`scripts/docs-catalog.ts`): a quiet, always-open label per
`GROUPS` entry in `GROUPS` order, then that group's pages by `order`. Top-level
folders such as `reference/` are extracted in place, so every page keeps its
URL. Do not hand-maintain a second page list.

The active page expands to show its outline: H2s, plus H3s while the outline
stays at 24 entries or fewer, on thin branch lines. The section in view is inked
and its branch tick takes the accent; the outline keeps it scrolled into view.
The sidebar foot holds the Theme selector and `llms.txt`, GitHub, and site links.

Search is a minimal dialog: a `title`-size field, an `esc` hint, and grouped results from
the static advanced index. ⌘K / Ctrl-K and `/` (when not typing) open it.
Exact, prefix, and word-prefix title matches move whole page groups forward,
leaving each heading/text hit with its parent. Failed index loading gets an
announced error, a genuine retry, and an all-documentation escape path; an error
must not masquerade as zero matches.

## Agent surfaces

Every page has a Markdown twin at its URL plus `.md` (also served for
`Accept: text/markdown`), advertised with `<link rel="alternate"
type="text/markdown">`. `/llms-full.txt` concatenates every page's Markdown in
sidebar order, each headed by its URL and exact source; `/llms.txt` is the
curated index and links to it. Each page has its own 1200×630 social card at
`/og/<slug>.png`, drawn with sharp in the reader's paper and ink.

## Responsive and interaction rules

- Above 860px the sidebar is a sticky column. At 860px and below it becomes a
  drawer behind a sticky top bar (menu, wordmark, search).
- The drawer is a native modal dialog holding the same tree and outline. Escape
  or a backdrop click closes it, focus starts on Close, Tab stays inside, and
  closing returns focus to the opening control. Opening search, or following a
  link, closes the drawer.
- Mobile navigation targets are at least `space.touch_min` tall. Icon controls have accessible
  names; decorative icons and arrows do not enter the accessible name.
- No horizontal page scroll at 320px or wider; only code and table panels scroll.
- Keep the token focus ring (`border.focus`, an outline at `focus_ring` width and
  offset) and a working skip-to-documentation link.
- Reduced motion shortens every token spring (`brand-tokens.css`); the reader also
  disables its remaining animation and smooth scrolling.
- Do not persist the entire document body between Astro routes: article, active
  navigation, outline, copy controls, and metadata must update together.

Before landing UI changes, inspect `/_design` in every toggle, then overview, an
article, and code/table-heavy reference pages at 320px, tablet, and desktop
widths in both themes. Exercise
Escape, Tab, skip navigation, copy success/failure, theme persistence, search
failure/retry, deep links, and route/back navigation on the built site.
`bun run verify:docs` automates the copy, discovery, ordering, outline, search
key, and drawer checks.

## Guardrails

- `bun run check` runs `scripts/check-style-literals.ts`: raw hex colours,
  pixel radii, `cubic-bezier`, literal durations in `transition`/`animation`,
  `box-shadow` literals, pixel `font-size` and physical inline properties are
  counted per file under `src/`. A file may not rise above
  `scripts/style-literals.baseline.json` and a new file may not add any. Only
  `brand-tokens.css` and `reader/tokens.css` own literals; motion scenes under
  `src/components/motion/` may opt out with a `style-literals: illustration`
  header. Lower a file's count when you touch it; rewrite the baseline only in a
  cleanup commit (`bun run scripts/check-style-literals.ts --write-baseline`).
  The target is an empty baseline.
- `scripts/brand-tokens.test.ts` fails when a stylesheet names a token the brand
  does not define, or when a mode the site relies on disappears.
- `/_design` (noindex, not in the sitemap) renders every role, the status ladder
  (colour, word and vector mark), the type roles, radii, elevation, states,
  glass, metal and the reader variant. Query toggles: `?mode=dark|light|system`,
  `?design=reader`, `?contrast=more` and `?forced=active` (previews of the token
  maps; the real modes follow the browser, so also check DevTools' emulation),
  and `?dir=rtl`.
